# Remaking ACID: Red-Team of the Layer-Level Pipeline

> **Scope — read this first.**
> This document covers **only the remake of ACID itself**: replacing or restructuring ACID's monolithic CP-SAT scheduler with a layer-generation + layer-assembly pipeline, and the LER-aware objective and scoring attached to it.
>
> It does **not** cover:
> - the **HAL modification** (placement and routing on multilayer superconducting hardware), or
> - **how HAL fidelity / heatmap information is imported back into the remade ACID.**
>
> Those are separate threads. Where this document mentions a connectivity-search outer loop, it treats the connectivity graph as an abstract input to ACID, with no assumptions about where it comes from.
>
> Companion document: the list of claims found *incorrect* in the previous conversation and in the problems document is kept separately (errata PDF, 16 Sept 2026) and is not repeated here.

## 0. Verdict

The previous conversation's five-step algorithm is roughly 40% real, 40% mislabeled, and 20% wrong.

- **Real:** the *decomposition*. A small master over a pool of layers, with layers generated by a subproblem, is textbook column generation for graph colouring and is the right shape.
- **Mislabeled:** most of the rigour claims attached to the layer generator (PST, Raghavan–Thompson, Expectation Propagation, reduced-cost fixing).
- **Wrong:** the "tile codes are hard" narrative and the spanning-tree / Wilson machinery, both of which dissolve on reading the actual papers.

The per-node-pmf layer generator survives only in one rigorous form, and that form is *not* per-node pmfs.

**Premise correction:** ACID reports **no runtimes** for any instance. "CP-SAT clearly doesn't scale on BB" is currently a hypothesis. It must be measured first (test T1), because if it is false the solver-replacement thread loses its justification and the project reduces to the connectivity-search + LER-objective thread — which is the stronger thread anyway.

## 1. How the revised algorithm should be structured

### 1.1 The problem, in ACID's own terms

- ACID specifies each contraction schedule uniquely by (1) a rooted spanning tree of the stabilizer's local connectivity graph and (2) a *timing*: a timestep per tree edge such that edges sharing a node are not simultaneous and edges farther from the root fire first. Some trees admit no valid timing.
- ACID builds a **scheduling graph**: nodes are quasi-stabilizers decorated with their schedule lists; edges carry the lists of mutually compatible schedule pairs.
- The "node = stabilizer, edge = possible conflict" graph in the current proposal **is** this scheduling graph.
- A **layer** is a set of (stabilizer, schedule) pairs, at most one per stabilizer, pairwise compatible.
- A **round** is an ordered sequence of L layers covering every stabilizer at least once and respecting the product-stabilizer ordering that ACID encodes with FLAG / RESET / COUNTER variables (ACID Appendix B).

If one schedule per stabilizer is fixed, "minimize L" is **graph colouring of the conflict graph** (layers = colour classes = independent sets). With schedule choice it is a list-colouring-like generalization.

This determines the structure: the standard exact method for colouring with many colour classes is **column generation with independent sets as columns** (Mehrotra–Trick 1996), whose pricing subproblem is max-weight independent set. Gualandi–Malucelli (2012) improve this by solving the pricing subproblem with constraint programming and using CP for heuristic solutions — which is exactly the proposed architecture: CP-SAT for the small pricing problem, LP/ILP for the master.

### 1.2 Revised pipeline

**Stage 0 — ACID front end, unchanged.**
Quasi-stabilizers, vAw bidiagonalization, scheduling graph, per-shape schedule enumeration with caching (ACID already caches per unique stabilizer shape). Add timing-depth pruning per shape if |C_i| grows. Do not replace this stage.

**Stage 1 — Layer generator = pricing subproblem.**
Input: prices π_i ≥ 0 per stabilizer (duals from the master; initially uniform).
Output: a feasible layer maximizing Σ π_i over the stabilizers it schedules.

Two pricers:
- *Exact pricer:* CP-SAT on the single-layer problem with a time limit and solution hints. This is a max-weight compatible set on a graph of degree ≤ 30 (see §4.1) — small.
- *Heuristic pricer:* weighted local search on the same problem (min-conflicts / constraint-weighting family), warm-started from previous layers.

"Iterate as you generate" lives here: stabilizers under-covered in the pool receive high prices, so the next layer works around them. That is the dual-price mechanism plus squeaky-wheel optimization, not an invented heuristic.

*Where the pmf idea goes:* if a distributional relaxation is wanted, the rigorous one is the **LP relaxation over the local marginal polytope** — variables x_{i,c} ∈ [0,1] with pairwise marginals μ_ij(c,c') = 0 on incompatible pairs. It is convex, its optimum is a bound, and it is solved by dual decomposition / MPLP. The product-of-pmfs (mean-field) version is non-convex and collapses. **Recommendation:** skip the relaxation entirely until CP-SAT pricing is shown to be too slow, because the pricing problem is small.

**Stage 2 — Master over the pool.**
CP-SAT with variables x_{j,t} (layer j at position t), t = 1..L, pool size ~10³.
- Constraints: coverage of every stabilizer; one layer per position; pairwise compatibility table P[j][j'] for adjacent positions (precomputed from ACID's gauge-ordering rules); product-stabilizer completion constraints ported from ACID Appendix B.
- Objective: Anker–Debroy's layer-local and pair-local terms (a, b, m, s₂) plus s₃ with state augmentation, using their weights (α, β, γ, δ) = (6, 5, 12, 2) until data exist to retune.
- Infeasible pool combinations found during search are stored as no-goods (combinatorial / logic-based Benders cuts).
- The LP relaxation of the covering master supplies duals for Stage 1.

**Stage 3 — Scoring.**
Halt-depth distribution from PropHunt §5.1 (expansion + F₂ rank check, MaxSAT stripped), ranked on N̂ · p^⌈d̂_eff / 2⌉. Where the detector error model is graph-like, Anker–Debroy Appendix C shortest-path counting is a polynomial-time exact version of the same quantity.

**Stage 4 — Connectivity outer loop (end goal, not the initial problem).**
Screening statistics first (2-edge-connectivity of local graphs, |C_i|, scheduling-graph degree distribution, spanning-tree counts via matrix-tree theorem); Stages 1–3 only on survivors.

### 1.3 Stripped from the design

- BTS / LLM-network framing (already dead).
- Fourier / convolution over schedule space (already dead).
- Wilson / matrix-tree state parameterization (demoted, §2.10).
- Raghavan–Thompson as a rigour guarantee.
- Expectation Propagation as "the standard method."
- Reduced-cost fixing applied to pmfs.

## 2. The algorithms, one by one

### 2.1 Column generation / Dantzig–Wolfe with a set-covering master

**Summary.** Write the round as: choose a multiset of layers (columns) covering every stabilizer, minimizing count or cost. Solve the LP over currently known columns; the LP duals price each stabilizer; the pricing subproblem finds a new column with positive reduced cost (Σ π_i over covered stabilizers exceeds the column's cost); repeat until none exists; then solve the integer master over the generated pool.

**Role and fit (red-teamed).** This is the correct name for "generate a pile of layers, then stitch." Both objections from the problems document resolve:
1. *"Unclear how to restructure into LP form."* The LP is the fractional set cover of stabilizers by layers — the same LP as fractional colouring. Anker–Debroy's pair-local terms do **not** fit a pure set-cover master; they belong in the integer master over positions (Stage 2), not in the LP used for pricing. Use the plain covering LP for duals and put the LER terms in the final CP-SAT master.
2. *"Probabilistic layer search contradicts independent linear subproblems / sounds like a worse SAT."* No. In real column-generation codes the pricing problem is attacked first by fast heuristics and only by an exact solver when the heuristics fail to find a positive-reduced-cost column. The Monte Carlo generator is a heuristic pricer; CP-SAT is the exact pricer; they are not in competition. What keeps this from being "a worse SAT" is that the LP dual bound on L is a genuine lower bound (this is how the best colouring lower bounds are obtained), and the master is small.

**Literature.** Mehrotra–Trick 1996; Gualandi–Malucelli 2012 (CP pricing); Held–Cook–Sewell 2012 (numerically safe bounds); Lübbecke–Desrosiers 2005 survey (Oper. Res. 53:1007).

**QEC use.** None found for syndrome-extraction scheduling. Not sure whether any qLDPC circuit paper has used column generation; none located.

**Speed.** Master LP: n_stab rows × |pool| columns — milliseconds. Pricing: see 2.3. Typical runs need tens to a few hundred pricing calls.

**Libraries.** OR-Tools (CP-SAT + GLOP), SCIP (branch-and-price via GCG), HiGHS for the LP.

### 2.2 Fractional covering via multiplicative weights (Plotkin–Shmoys–Tardos)

**Summary.** A Lagrangian-relaxation algorithm for LPs of the form "cover every row" over an implicitly given polytope. Maintains prices on rows, calls an oracle "given prices, return the best column," updates prices multiplicatively; ε-approximate in O(ρ ε⁻² log m) oracle calls. PST's contribution is a running-time analysis for this kind of Lagrangian scheme.

**Role and fit (red-teamed).** The suspicion is half right. PST *does* apply to the covering LP — it is an alternative to the simplex-based master in 2.1, and the prices are exactly the mechanism by which past layers feed into the next layer's cost. So "filter previous layer data into the cost function" is the point of the method, not a misuse.

What was wrong previously: the oracle is max-weight compatible set, which is NP-hard, and DP on acyclic clamp sets does not implement it. PST's guarantee assumes an exact or provably approximate oracle. With CP-SAT as the oracle, the guarantee holds; with a heuristic pricer it does not. Since the master LP is tiny, PST buys nothing over simplex here. **Keep the price concept; drop PST as the named algorithm unless the master becomes large.**

**Literature.** PST 1995; Garg–Könemann 2007 (SIAM J. Comput. 37:630); Arora–Hazan–Kale survey.

**QEC use.** None found.

**Speed.** Dominated by oracle calls; the ε⁻² dependence makes it worse than simplex at these sizes.

**Libraries.** Trivial to hand-code; no standard package.

### 2.3 The pricing subproblem: max-weight compatible set

**Summary.** Given prices π, find a layer maximizing Σ π_i: choose at most one schedule per stabilizer so that all chosen pairs are compatible. This is max-weight independent set in the (stabilizer, schedule) conflict graph with a "one per stabilizer" side constraint.

**Role and fit.** This *is* the single-layer problem. Note what it is not: it is not "minimize conflicts among all stabilizers." A layer legitimately leaves stabilizers out; the prices decide which. The generator's original objective ("optimize conditioned pmfs to minimize expected conflicts") implicitly tried to schedule everything — the wrong objective for a single layer.

**Exact pricer.** CP-SAT with `AddHint` from the previous layer, time-limited. Anker–Debroy's practice — seed with the heuristic schedule, cap at 5 minutes, output guaranteed no worse than the seed — is the template.

**Heuristic pricer — the rigorous home of the Monte Carlo idea.** Weighted local search (min-conflicts with constraint weighting: breakout method, Morris 1993; DLM, Shang & Wah 1998), or simulated annealing on the Potts-like energy

  E(c) = −Σ_i π_i · [i scheduled] + λ Σ_e B_e(c).

Sampling from exp(−E/T) is Gibbs sampling / annealing. This *is* the "Gibbs distribution" derived in the previous conversation, treated honestly as a joint MRF rather than a product of pmfs. Simulated annealing for colouring is the classical benchmark (Johnson et al. 1991, Oper. Res. 39:378).

**QEC use.** Colouring by local search is old. In QEC, AlphaSyndrome uses MCTS over schedules (different search, related space) and is a competitor.

**Speed.** Conflict graph for BB-144-hex: 144 nodes, degree ≤ 30, |C_i| in the tens → single-layer CP-SAT instances of ~10³–10⁴ booleans. Expected sub-second to seconds — **a guess; measure (T2).**

**Libraries.** OR-Tools CP-SAT; RC2 in PySAT for MaxSAT-style pricing; local search hand-coded.

### 2.4 Randomized rounding (Raghavan–Thompson) and concentration

**Summary.** Solve an LP relaxation, treat fractional values as probabilities, sample independently; Chernoff bounds show linear constraints are violated by at most an O(log)-factor with high probability.

**Role and fit (red-teamed).** Sampling one schedule per stabilizer from LP marginals (or pmfs) is randomized rounding in the generic sense. The previous claim that "this is the theorem that makes sample-and-hope rigorous" is wrong on two counts:
- (a) RT's Chernoff argument is for constraints linear in independent variables. The conflict count Σ_e B_e is **quadratic** in the sampled choices, so the applicable bound is McDiarmid's (bounded differences), with a variance term ∝ Σ_i deg(i)², which is loose at degree 30.
- (b) A layer needs **zero** conflicts, and no concentration bound gives that.

What rounding actually provides is a warm start for repair (drop the lower-priced endpoint of each conflicting edge, then greedily re-insert) — a reasonable heuristic pricer with no guarantee.

**Literature.** RT 1987; McDiarmid 1989.

**QEC use.** None found for scheduling. LP relaxations appear in QEC as LP decoders — a different problem.

**Speed.** O(n_stab + edges) per sample.

**Libraries.** numpy.

### 2.5 Forest-block updates ("chain clamping") = structured mean field / block coordinate descent

**Summary.** Choose a set of clamped edges forming a forest. The joint over the nodes touched by the forest, with all other nodes fixed, is a tree-structured factor graph; its optimum (MAP) or marginals are exact by dynamic programming in O(k |C|²).

**Role and fit (red-teamed).** The intuition — clamp edges one after another in a line and optimize neighbouring pmfs jointly — is sound, and the previously given names (structured mean field, Saul & Jordan 1996; cluster variational method, Yedidia–Freeman–Weiss 2005) are the right names in the inference literature.

But be clear which problem the DP solves: with neighbours fixed it is a **block-coordinate descent step** on the single-layer problem — a large-neighbourhood-search move whose neighbourhood is a forest. Describe and implement it that way: LNS with a tree-structured neighbourhood; the exactness claim is simply "MAP on a tree is exact." The cluster variational method (Kikuchi region graphs, generalized BP) is heavier than needed and inherits GBP's convergence problems.

**Literature.** Saul–Jordan 1996 (NIPS); Yedidia et al. 2005 (IEEE Trans. IT 51:2282); LNS: Shaw 1998; adaptive LNS: Ropke–Pisinger 2006.

**QEC use.** None found for scheduling.

**Speed.** O(k |C|²) per block — trivially cheap.

**Libraries.** Hand-code, or express the block as a CP-SAT sub-model.

### 2.6 Mirror descent with entropic Bregman divergence / MWU

**Summary.** The step min_q ⟨g, q⟩ + (1/η) KL(q ‖ q_old) has closed form q ∝ q_old · exp(−η g). This is exponentiated gradient (Kivinen–Warmuth), mirror descent with negative entropy (Beck–Teboulle 2003), and the multiplicative-weights update.

**Role and fit (red-teamed).** The identity is correct, and "keep the new pmf close to the old one via KL" is exactly this. The previous conversation's error was calling it *the anti-collapse mechanism*. It is a **step-size control**: on an objective linear in each q_i the iterates still drift to vertices, just more slowly, and the √(T log N) regret bound says nothing about iterates staying in the interior.

Genuine diversity requires an **entropy term in the objective** — the original "entropy metric to push toward uniformity" proposal — which turns the problem into minimizing a mean-field free energy at temperature λ. Both together form standard entropy-regularized MWU; neither alone does what was claimed.

**Literature.** Beck–Teboulle 2003; Arora–Hazan–Kale 2012.

**QEC use.** Not for scheduling.

**Speed / libraries.** O(|C|) per node per step; numpy.

### 2.7 Mean field vs. the local-polytope LP relaxation (answers to guiding questions 1a–1f)

**1a — Relax the pmfs to continuous / group schedules?**
A pmf already is continuous; the question is which functional. The product-of-pmfs expectation E[Σ B_e] = Σ_e q_iᵀ M_e q_j is multilinear → non-convex → vertex collapse. The convex alternative is the MAP-LP over the local polytope: node marginals μ_i and edge marginals μ_ij, mutually consistent, with μ_ij(c,c') = 0 on incompatible pairs.
Grouping schedules: a "slot occupancy" factorization gives a low-rank *upper bound* on P(conflict) via a union bound over (qubit, timestep) slots — usable as a cheap surrogate, not exact.

**1b — Is optimizing conditioned pmfs NP-hard, and are approximations?**
Computing marginals of the product distribution conditioned on constraints is #P-hard in general (Roth 1996), and even approximate inference is NP-hard (Dagum–Luby 1993, Artif. Intell. 60:141). On a forest it is polynomial (2.5). The LP relaxation is polynomial but fractional.

**1c — Deconditioning back to an overall pmf.**
There is no standard "Bayesian map back," because B_e is a deterministic function of the node choices, not a separate random variable. Two honest options:
- keep the clamp (decimation — the standard move in BP/SP-guided decimation), or
- relax it via Jeffrey conditioning: q_new = π · q(· | clamp) + (1 − π) · q — O(|C|), no inference needed.
EP is discussed in 2.8.

**1d — Convexity, global minima, local minima.**
Product-pmf objective: non-convex, many local minima; the random-CSP literature (Krzakala et al. 2007, PNAS 104:10318) shows clustered solution spaces near hardness thresholds, though for random rather than structured instances. LP relaxation: convex, no local minima, but fractional. **No formulation is both per-node-pmf and convex.**

**1e — Mapping the final result to actual layers.**
- (i) Random sampling → 2.4.
- (ii) Restricted SAT over top-k schedules per node → confidence-based partial fixing (Neural Diving) / restricted-master heuristic (column generation).
- (iii) Warm starting → CP-SAT solution hints, or LP-guided diving (Berthold 2006, *Primal heuristics for MIPs*, TU Berlin thesis): take the argmax of each pmf as a hint, or fix high-confidence variables and solve the residual.

**1f — Has this been done in literature, and how does it connect?**
Option (ii) is done in Nair et al. 2020 (fix by confidence, solve the remainder with SCIP) and Han et al. 2023 (trust region instead of hard fixing). The connection is direct: their predicted marginals play the role of these pmfs. **Not sure:** whether Neural Diving's confidence thresholds transfer to hand-built (not learned) pmfs; nobody has tested that.

**Literature.** Wainwright–Jordan 2008 (local polytope, tree-reweighted); Globerson–Jaakkola MPLP (NIPS 2007); Komodakis et al. dual decomposition (PAMI 2011).

**QEC use.** LP decoding of quantum codes uses the same polytope family for a different problem; nothing for scheduling.

**Speed.** MPLP / dual decomposition: O(edges × |C|²) per sweep.

**Libraries.** Any LP solver for the exact LP; OpenGM or hand-code for MPLP.

### 2.8 Gibbs distributions, I- vs M-projection, α-divergence (the EP question)

**The Gibbs claim.** Minimizing KL(q ‖ q_old) subject to E_q[B_e] ≤ τ_e gives

  q ∝ q_old · exp(−Σ_e λ_e B_e), λ_e ≥ 0.

This is Csiszár 1975 (I-projection onto a linear family); the max-entropy special case is Cover & Thomas Thm 12.1.1. **Not bullshit.** But this q is a joint MRF, not a product of per-node pmfs, so it supports the annealing pricer of 2.3, not the per-node design.

**EP.** Minka 2001. EP approximates p ∝ Π_a f_a(x) by a product of tractable site terms: form the tilted distribution (one exact factor × cavity), M-project onto the family, divide out the cavity, iterate. The previous mapping (tilted = conditioned block joint; project = moment match; divide cavity) correctly describes EP. Calling it "the standard method" for this pipeline is not correct: for a product family the M-projection is just the product of marginals, computed exactly by DP on the forest (2.5). EP's cavity machinery matters only when the same block is revisited repeatedly.

**The tension and its resolution.** EP's M-projection (min KL(p ‖ q)) is moment-matching / mass-covering; the trust region's I-projection (min KL(q ‖ p)) is mode-seeking. The literature's answer is Minka's **α-divergence family** (Power EP 2004; "Divergence measures and message passing" 2005): α → 1 is M-projection (EP), α → 0 is I-projection (variational / mean field), fractional α interpolates and is often better behaved. The two are two ends of one dial; choose α once and use the same divergence for both the update and the projection.

**QEC use.** None for scheduling.

**Speed / libraries.** DP on forest, O(k |C|²); no library needed.

### 2.9 MUS extraction and combinatorial / logic-based Benders cuts

**Summary.** A MUS is a minimal jointly unsatisfiable subset of constraints (Liffiton–Sakallah 2008; tools: MUSer2, PySAT `musx` / `optux`). Combinatorial Benders (Codato–Fischetti 2006): a pure-integer master holds combinatorial information about feasible integer combinations; a slave problem validates master solutions and returns inequalities derived from minimal infeasible subsystems. The general form is logic-based Benders (Hooker–Ottosson 2003).

**Role and fit (red-teamed).** Two different uses were conflated:
- (a) **Within the layer generator:** an infeasible clamp set yields a no-good clause on schedule choices — useful to the pricer (CDCL-style learning).
- (b) **In the master:** an infeasible combination of pool layers (fails the gauge-ordering check) yields a cut Σ_{j∈S} x_j ≤ |S| − 1. This is a legitimate combinatorial Benders cut, provided the master is an ILP and the subproblem is ACID's feasibility check.

The "certified lower bound on L via a clique" claim is narrower than stated. It holds only for pairs with an **empty** compatibility list in the scheduling graph (e.g. anticommuting quasi-stabilizers), which can be read off directly — no MUS needed. A MUS from a clamp shows a *particular set of choices* is infeasible, not that the stabilizers are pairwise unschedulable.

**Literature / QEC use.** As above; none in QEC scheduling.

**Speed.** MUS extraction is worst-case exponential but fast on small cores (PropHunt's approach relies on small witnesses).

**Libraries.** PySAT (RC2, musx); OR-Tools CP-SAT (assumption-based cores via `sufficient_assumptions_for_infeasibility`).

### 2.10 Spanning-tree parameterization (matrix-tree theorem + Wilson's algorithm) — demoted

**Summary.** Weighted spanning trees on a graph form a log-linear family whose normalizer is a determinant (Kirchhoff), and Wilson's algorithm samples exactly from it by loop-erased random walk from a chosen root.

**What was proposed.** Do not store a pmf over schedules; store per-edge weights on each local connectivity graph, inducing a distribution over spanning trees; sample trees with Wilson; state per stabilizer becomes O(|E_i|). Framed as the analogue of randomized-rounding routers that store edge flows and round by random walk rather than storing all paths.

**Red team.** Mathematically correct, wrong target:
- ACID attributes its schedule blowup (superdense colour code, weight 8) to two redundant local edges **combined with** four contraction timesteps. The timing factor is part of the explosion, and trees carry no timings. Some trees have no valid timing at all.
- Pairwise compatibility depends on per-timestep qubit occupancy and on Pauli-support propagation, so E[B_e] under the tree measure is not a determinant or anything else closed-form.
- For the codes in scope (hexagonal local graphs: 6 trees × 6 roots before timings), enumeration is trivial and ACID already caches it per shape.
- The randomized-rounding-router analogy is real (PathFinder-style routers keep edge congestion costs and reroute by path search), but its relevance is state size, and state size is not the bottleneck here.

**Decision.** Keep the matrix-tree *count* as a connectivity-screening statistic (Stage 4). Drop the sampling machinery from the core design.

**Libraries.** networkx (`random_spanning_tree`).

### 2.11 Diving, RINS, predict-and-search, Neural Diving (1e-ii/iii and the trust-region question)

**Neural Diving (Nair et al. 2020).** A trained network generates multiple partial assignments of integer variables; each resulting sub-MIP is completed with SCIP; the best completion is kept.
- **Open source?** No official DeepMind release for the 2020 paper. Third-party reimplementations exist (e.g. github.com/namogg/Neural_Diving), and DeepMind released later neural-LNS code.
- **Fit:** analogy only. It requires training on solved instances, which do not exist for the target codes (that is the premise). Fine as a design pattern; wrong as "the architecture."

**Predict-and-search (Han et al., ICLR 2023).** Predicts marginals, then searches for the best feasible solution inside a trust region around the prediction instead of hard-fixing variables; the authors report it outperforms fixing-based strategies by avoiding sub-optimal or infeasible sub-problems. Code is public.

**This answers "can an edge variable be partially selected rather than clamped to 0?" rigorously, in two forms:**
- *Combinatorial form:* the trust region is a Hamming-ball constraint added to the exact solver, Σ_{i: predicted 1} (1 − x_i) + Σ_{i: predicted 0} x_i ≤ Δ. Its ancestor is local branching (Fischetti–Lodi 2003). Here: instead of clamping B_e = 0 for a set S of edges, add Σ_{e∈S} B_e ≤ Δ to the pricer's CP-SAT model (cardinality constraints are native in CP-SAT).
- *Distributional form:* the moment constraint E[B_e] ≤ τ_e of 2.8.

So "the edge should be close to 0 on average" is rigorous in both forms.

**Diving / RINS.** LP-guided diving (Berthold 2006) fixes variables iteratively from LP values; RINS (Danna et al. 2005) fixes variables where incumbent and LP agree and solves the rest. These are the correct names for "warm-start a layer ILP with the probabilities" (1e-iii): argmax as hints, or fix high-confidence variables and solve the residual.

**QEC use.** None found. **Speed.** One sub-MIP per sample; parallel. **Libraries.** OR-Tools (hints, cardinality), SCIP.

### 2.12 "Iterate as you generate" (guiding question 2f)

Three existing mechanisms, in decreasing rigour:
1. **LP duals from the master** — the principled version, already in 2.1; under-covered stabilizers get high prices automatically.
2. **Squeaky-wheel optimization** (Joslin–Clements 1999): after each construction, raise the priority of items handled badly, then reconstruct. "Bias the Monte Carlo toward least-present stabilizers" is exactly this.
3. **Cross-entropy method** (Rubinstein 1999): treat the sampling distribution's parameters as the object to tune and update them toward elite samples. If a sampling-based pricer is kept, CE is the standard way to tune its distribution instead of hand-designed biasing rules.

All three are cheap; none has a QEC precedent that was found.

### 2.13 Scoring: PropHunt ambiguity sampling and Appendix-C path counting

PropHunt's witness search uses the Loandra MaxSAT solver with a 360 s timeout per call. The metric path needs only the expansion + F₂ rank check; the "extremely cheap linear-algebra solve" claim holds only with MaxSAT stripped, and the aggregate sampling cost still has to be measured.

For circuits whose detector error model is graph-like, Anker–Debroy's Appendix C quantity (number of minimum-weight paths in the qubit/detector-support graph) is a polynomial-time BFS count — exact, no sampling. For hypergraph DEMs — which ACID itself sometimes produces, noting they do not always admit a decoding-graph approximation — the sampled halt-depth distribution is the general version. Same target at two fidelities.

### 2.14 Weighting PropHunt-based vs Anker–Debroy heuristics (guiding question 2b)

There is no way to weight them without data. Anker–Debroy's weights were chosen from space-time arguments and are untuned; theirs is the only validated linear proxy.

**Protocol:**
1. Build a circuit set at fixed d with spread in LER. Their Figure 13 regime is ideal: their objective is held roughly constant while LER varies.
2. Compute all five Anker–Debroy terms and the halt-depth statistics per circuit.
3. Fit a rank regression to LER on half the set; test Spearman ρ on the other half, always against the d_eff-only null.
4. Report whether the ambiguity terms add rank power over the five terms.

Anything else is post-selection.

### 2.15 vAw choice and layer compatibility (guiding question 2c)

Nothing was found in the literature relating gauge-basis choice to schedule compatibility. What exists: Anker–Debroy's weight-1 gauge result (8.2% / 14.9% LER improvement at 1% / 3% dropout) and arXiv:2604.05874's Proposition 1 (a normalized generating set per defective qubit).

A principled version of "pick v, w that admit more layer pairings" would be: enumerate the valid (V, W) bidiagonalizations (a coset of the automorphism group of the anticommutation matrix), and for each count feasible adjacent-layer pairs in the current pool. **Not sure** this is tractable beyond small defect clusters, and there is no citation for it — treat it as unclaimed territory.

### 3.1 Contained tests with published baselines

**T1 — Is the solver the bottleneck?**
Run ACID's open-source CP-SAT on BB-144 / BB-288 (hex and degree-5) at 0–3 dropouts, with and without a 300 s time limit + hints.
*Baseline:* reproduce ACID's own L distributions (Appendix D); the runtime is the new datum. Anker–Debroy's pattern — optimum found in ~5 min, the rest spent proving optimality — is the expected shape.
*Decides:* whether Stages 1–2 are needed at all.

**T2 — Column generation recovers known L.**
Pure covering, no LER terms. On dropout-free surface, BB-hex, and colour code, master + pricing must return L = 2.
*Baseline:* ACID states that without dropouts these codes admit two-layer constructions measuring half the stabilizers per layer, and ACID rediscovers them. Expect L = 2 and LP dual bound = 2.

**T3 — Tile bulk equals BB bulk.**
Compute the scheduling-graph degree distribution for the [[288,8,12]] family and BB-144-hex using ACID's own code.
*Expected:* both ≤ 30 in the bulk (§4.1); tile boundary checks lower. Settles whether the previous tile-code narrative was wrong.

**T4 — No-dropout acceptance for the master objective.**
Minimizing the Anker–Debroy objective on the dropout-free surface code must return one of the four symmetric canonical circuits (their stated result). If the ported master does not, the port is wrong.

**T5 — Mean-field collapse.**
Naive mean field with energy-only objective on the d = 5 surface code: after one coordinate sweep all pmfs should be point masses (theory baseline). Add λ · H(q) and observe an interior fixed point. Cheap; settles whether any per-node-pmf variant is worth keeping.

**T6 — Rounding feasibility rate.**
From the local-polytope LP solution (or pmfs), sample 10⁴ layers; record the zero-conflict fraction and the conflict-count distribution against the McDiarmid bound.
*Kill criterion:* if the feasible fraction is < 10⁻² on BB-144, sampling-then-repair is not a viable pricer.

**T7 — Halt-depth reproduction.**
Implement PropHunt §5.1 only; on surface d = 3, 5, 7, reproduce their subgraph-size-vs-d_eff saturation curve (baseline: their figure). Then check that the minimum halt depth equals Stim's shortest graphlike error weight on the same circuits (d_eff null).

**T8 — Figure-13 test bed.**
Using Anker–Debroy's solver-time sweep circuits (50–120 s), where objective is near-constant and LER varies: compute the halt-depth prefactor N̂ and its Spearman ρ against their LER. Cleanest experiment in the project; currently unassigned.

**T9 — L-generalization.**
BB-hex, same dropout pattern, L = 2/3 vs forced L = 4, at **equal physical-operation count**, Stim LER. Decides whether "min-L is the wrong objective" transfers off the surface code.

## 4. Other points from the specific questions

### 4.1 Tile codes — read against the papers

**What the PRL actually defines.** A tile is a subset of edges of a B × B square box, excluding the top row and rightmost column; condition (T2) fixes the Z-tile from the X-tile so that X and Z tiles always overlap evenly. Headline codes: [[288,8,12]] with weight-6 and [[288,8,14]] with weight-8 stabilizers in 3 × 3 boxes; [[288,18,13]] and [[512,18,19]] with weight-8 in 4 × 4 boxes (kd²/n up to ~12.7). Codes were found by brute-force search.

**Which paper the polynomial families come from.** The four weight-6 families with f = 1 + x + x^a y^b, g = 1 + y + x^c y^d and kd²/n from 1.78 to 4.00 are Bae & Park's Table 1, which they take from Liang–Eberhardt–Chen — not from the PRL. The previous handoff merged the two.

**Hardness.** Bulk checks share a qubit only when the anchor difference lies in a difference set of the three-monomial supports:
- same-type neighbours: ≤ 6 (via f) + 6 (via g) = 12;
- opposite-type neighbours: ≤ 9 + 9 = 18;
- total bulk scheduling degree ≤ 30 — **identical to a weight-6 BB code**.
"Degree ~50" counted box overlaps, not shared qubits. The bulk of a weight-6 tile code is the same scheduling problem ACID already solves for BB.

**Subgraph restriction.** Not just reasonable — it is the natural structure. Solve the translation-invariant bulk once on a fundamental domain (what arXiv:2608.19917 exploits for clean codes), and re-solve only in a window around boundaries and dropouts (LUCI's locality principle). Window size is set by the polynomial range (2–3 lattice sites). Nothing in the papers requires accepting "more layers overall"; the PRL only anticipates that the BB QEC cycle can be adapted to tile codes.

**What tile codes genuinely lack** is an ancilla-free connectivity graph. The routing paper is ancilla-based SWAP routing on a strictly nearest-neighbour square lattice, with a roughly two- to three-fold threshold penalty (SI1000 threshold ~0.23–0.31% unrouted vs ~0.11–0.13% routed).

### 4.2 Routing words → 2BGA / radial codes

Bae & Park scope their routing-word scheme to planar tile families. The mechanism is a global word over SWAP directions executed by every ancilla in lockstep, which requires (i) a translation-invariant bulk on a lattice and (ii) a fixed ancilla-to-check offset. Non-abelian 2BGA codes have no lattice translation action; radial codes are non-planar quasi-cyclic lifted-product codes. **The extension claim is unsupported.**

The transferable abstraction — search over words in a small alphabet of global permutations commuting with the code's symmetry group — is plausible, but it would require inventing both the alphabet and a symmetry-respecting hardware embedding, neither of which exists in that paper. The 2BGA and radial papers were not fetched in this session; check their symmetry structure before writing anything down.

### 4.3 LER surrogate for the connectivity search (the "second project")

What exists, by fidelity:

- **Graph-level screening (no scheduling):** local 2-edge-connectivity (prior project finding), spanning-tree counts (matrix-tree), scheduling-graph degree distribution, Tanner-graph girth / short cycles (classically, short cycles and trapping sets drive BP error floors — Richardson 2003, "Error floors of LDPC codes"; analogous quantities matter for BP+OSD-decoded qLDPC). Cheap; unvalidated as LER predictors for ancilla-free circuits.
- **Schedule-level linear proxies:** Anker–Debroy's five terms — validated on the surface code only; the authors state generalizing to higher-connectivity codes is open.
- **Distance level:** d_eff via Stim's `shortest_graphlike_error` / `search_for_undetectable_logical_errors` (cheap for graphlike DEMs, expensive for hypergraph DEMs). PropHunt Figure 1(b) shows d_eff alone is insufficient.
- **Prefactor level:** Appendix-C path counting (exact, graphlike only); PropHunt halt-depth distribution (sampled, general); entropic-prefactor theory (Beverland–Brown, arXiv:1812.05117).
- **Stratified / rare-event simulation:** Bravyi–Vargo 2013 (arXiv:1308.6270) splitting; Ye–Palsberg arXiv:2602.04921 stratified LER. These are faster-than-Monte-Carlo LER *estimators*, not proxies — the right validator for any proxy.
- **Learned / search objectives:** AlphaSyndrome's error-propagation objective (competitor).
- **New 2026 items seen only in citation lists, not yet read:** arXiv:2603.01628 (distance-preserving syndrome extraction for arbitrary layouts at minimum depth), arXiv:2603.05481 (high-performance syndrome extraction circuits for quantum codes), arXiv:2609.12020 (RL for syndrome extraction, Sept 2026). All three sit directly on this thread and must be read before any novelty claim.
- **Does not exist:** a validated cheap LER surrogate for ancilla-free qLDPC circuits, or any test that "key properties of a layer pool" predict LER. That intuition has no prior art; it is a hypothesis to test with T8-style rank correlation, nothing more.

**Best heuristics for the pruning stage, ranked by confidence:**
1. Every check's local graph is 2-edge-connected after dropout.
2. |C_i| ≥ some minimum per shape (schedule flexibility).
3. Scheduling-graph maximum degree.
4. Tanner-graph girth.
5. Spanning-tree count.

Only (1) has evidence behind it.

### 4.4 Three-round schedules and "time squishing" — minimal validation

The confound: fewer rounds change both measurement frequency *and* detector shape. Two tests separate them:
- **(a) Frequency-matched:** construct 3-round and 4-round schedules with identical per-operator measurement-count histograms (pad the 3-round schedule with redundant measurements); compare LER at equal operation count. If the gap persists, the spatial / shape effect is real.
- **(b) Path-count:** compute Appendix-C shortest-path length and count for both. If the 3-round loss is explained by path count alone, it is a prefactor effect, not frequency.

Both are Stim-only and use Anker–Debroy's public setup as the baseline.

### 4.5 Speed answer for guiding question 1

The per-node-pmf generator as specified is not fast in any meaningful sense: each pass is O(edges × |C|²) and many passes are needed with no convergence guarantee (non-convex). The CP-SAT pricer on a degree-≤30 graph is what to benchmark. If it is sub-second, the entire relaxation thread is unnecessary for the initial problem and matters only for the 10³–10⁵-call connectivity loop, where graph-level screening should eliminate most calls anyway.

### 4.6 Why this beats "just run CP-SAT" (guiding question 3)

- **(a) Non-linear terms:** the path-count / ambiguity prefactor lives in the scoring stage, outside any ILP. That is the concrete thing an ILP-only architecture cannot do, and Anker–Debroy say so explicitly.
- **(b) Accepting worse results for speed:** yes, for the ranking objective in the connectivity loop.
- **(c) Beating ACID on BB LER:** plausible only because ACID optimizes L and "cram-in" counts, and its own author reports that a single dropped coupler *improved* LER on BB-144 (implying sub-optimal selection in the dropout-free case). A master with an LER-aware objective at equal operation count could beat it — but T9 must be run first, or the comparison is not at equal cost.
